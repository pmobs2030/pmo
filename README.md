# لوحة تحكم الهوية — وسيط AI (Design Tokens Panel)

بروتوتايب Angular مستقل يعطي تحكمًا حيًا كاملاً بكل قيم الهوية البصرية (الوضعان الداكن والفاتح) —
مصدر كل قيمة هنا هو ملف الهوية المعتمد. خضع لتدقيق خماسي مستقل (أمان، جودة كود، تكامل، QA، مطابقة
هوية) بتاريخ 2026-08-17 — كل النتائج المؤكدة صُححت، التفاصيل الكاملة بـ`02_سجل_القرارات.md` (القرار 20).

## ⚠️ تحذيرات إلزامية قبل الدمج بمشروع حقيقي — اقرأها أولاً

1. **إصدار Angular**: هذا المشروع يستخدم `provideAppInitializer` (يتطلب Angular 19+) و`@for`/`@if`
   وsignals (تتطلب 17+). **لا يُدمج بمشروع أقدم من Angular 19 بدون تعديل جذري.**
2. **خطر تعارض متغيرات CSS**: `DesignTokensService.applyAll()` يكتب على `document.documentElement`
   مباشرة (توكنات مثل `--pg`, `--txt`, `--teal`...) — إذا كان مشروعك الحقيقي يعرّف نفس الأسماء، فتح
   هذه اللوحة سيُعيد تلوين **كل الصفحة الحالية فورًا**، ليس فقط معاينة معزولة. **لا تربط `loadAndApply()`
   بـ`provideAppInitializer` الجذري بمشروعك الحقيقي كما هو — اربطه فقط عند تفعيل مسارات اللوحة نفسها.**
3. **أسماء ملفات الأصول**: الملفات تحت `assets/design-tokens/` (مُنظَّمة بمجلد فرعي خصيصًا لتفادي تعارض
   أسماء مع ملفات حقيقية بمشروعك مثل `icons.json`). لا تُعِد تسميتها لملفات بجذر `assets/` مباشرة.
4. **`bypassSecurityTrustHtml`** مستخدَم لعرض أيقونات SVG (`icon-tokens.ts`) — آمن اليوم لأن المصدر
   ملف JSON ثابت بالبناء. **إذا رُبط لاحقًا بمصدر بيانات حي (API، رفع مستخدم)، يصبح ثغرة XSS مخزّنة
   حقيقية** — يجب تعقيم فعلي (DOMPurify أو قائمة سماح مغلقة) قبل ذلك، راجع التعليق بالكود.
5. شغّل `npm audit` من جديد بعد الدمج بمشروعك الحقيقي (شجرة الاعتماديات ستكبر).

```
src/app/
├── core/
│   ├── theme-mode.service.ts       ← مصدر واحد مشترك لحالة الوضع (داكن/فاتح) لكل الخدمات
│   ├── design-tokens.service.ts    ← الألوان/الخطوط/المقاسات/الظلال/المكوّنات + سلالم الألوان + تصدير CSS
│   ├── icons.service.ts            ← مكتبتا الأيقونات (عامة 74 + AI 5) + منطق الاستبدال الحصري
│   └── levels.service.ts           ← نظام المستويات الـؘ15×3 (ألوان تختلف بالوضعين + نسب/نقاط مشتركة)
├── admin/
│   ├── color-tokens/               ← صفحة "القيم" — مبدّل داكن/فاتح (t-toggle)
│   ├── icon-tokens/                 ← صفحة "الأيقونات"
│   ├── levels/                      ← صفحة "المستويات"
│   └── export-css/                  ← صفحة "تصدير CSS" — ملف واحد يغطي الوضعين معًا
└── app.config.ts                    ← provideHttpClient + تحميل الوضعين عند الإقلاع (راجع تحذير #2)

public/assets/design-tokens/       ← مصدر البيانات الحقيقي الوحيد
├── tokens.json / tokens-light.json      ← 201 / 205 توكن (تماثل كامل عدا 4 توكنات site/dashboard موثّقة)
├── icons.json                           ← 4 مكتبات: عامة(74) + AI معتمدة(5) + AI مقترحة(9، موسومة) + ws-site(80)
├── levels.json / levels-light.json      ← 45 مستوى، الألوان تختلف فعليًا بين الوضعين (مصدر: buildLevelColors)
├── levels-perks.json                    ← نصوص مزايا كل نطاق مستويات (3 أنواع × 3 نطاقات)
└── content-rules.json                   ← القواعد المعتمدة (11) وقاموس المصطلحات (6)
```

## الحالة بعد التدقيق الخماسي (2026-08-17)

- **الوضعان الداكن والفاتح**: مكتملان، متماثلان بنيويًا، مبنيان من نفس منهجية الاستخراج من ملف الهوية.
- **الأمان**: صفر أسرار مسرّبة، صفر ثغرات باعتماديات (`npm audit` نظيف)، CSS injection بالتصدير مُغلَق
  (`assertSafeCssValue`)، خطر `bypassSecurityTrustHtml` موثّق بوضوح (انظر تحذير #4).
- **جودة الكود**: `strict: true` مفعَّل، `ng build` (dev + production) نظيف بدون أي تحذير، إصلاح فجوات
  SSR (`isPlatformBrowser` بكل استدعاء DOM)، معالجة أخطاء HTTP، إصلاح خلل تعديل مباشر لحالة الـsignal.
- **مطابقة الهوية**: مكتبة الأيقونات أُعيدت بناؤها بالكامل من `iconDefs` (المصفوفة الرسمية الوحيدة
  بالهوية، 74 عنصر) بدل استخراج يدوي من الـsprite بلا قائمة اعتماد. ألوان المستويات بالفاتح (كانت
  غائبة كليًا) أُضيفت (`levels-light.json`، محسوبة من نفس صيغة `buildLevelColors(true)` بالهوية).
- **توسعة كاملة (2026-08-18)**: أُضيفت مكتبة أيقونات الموقع العام `ws-site` (80 عنصر، 4 مجموعات،
  تعيد استخدام أشكال `i-*` بتسمية موقع مختلفة)، 9 أيقونات AI مقترحة غير معتمدة (موسومة "مقترح" بوضوح،
  صفحة الأيقونات)، نصوص مزايا المستويات (`levels-perks.json`، صفحة "المستويات والمزايا")، القواعد
  المعتمدة وقاموس المصطلحات (`content-rules.json`، صفحة جديدة "القواعد والمصطلحات").
- **التعارضان المصدريان** (`--navy-dashboard` .96/.92، وحدود التركيز .35/.4): لم تُرجَّح قيمة تعسفًا —
  عُرضا كخيارين قابلين للنقر (لوحة ألوان) على نفس الحقل بصفحة "القيم"، القيمة الافتراضية محفوظة والبديل
  الموثّق متاح بنقرة واحدة.
